## Evidence and end-to-end traces

- Academic: `frontend/lib/src/features/academic/presentation/pages/academic_management_page.dart` -> `data/datasources/academic_remote_data_source.dart` -> `modules/academic/api/AcademicHierarchyController.java` -> `application/AcademicHierarchyService.java` -> AcademicYearRepository/ClassEntityRepository/SectionEntityRepository/DivisionSubjectRepository -> academic_years/classes/sections/division_subjects. `getTeacherDetails` reads SubjectTeacherMappingRepository while `addDivisionSubject`/`updateDivisionSubject` only write DivisionSubjectRepository. `toDivisionResponse` executes three related queries per division. V14's initial mapping backfill is a one-time migration, not ongoing synchronization.
- Students/parents: `students_page.dart`, `student_section_detail_page.dart`, `student_profile_page.dart` -> StudentsRepositoryImpl/StudentsRemoteDataSource -> StudentController -> StudentService/StudentImportExportService/StudentMapper -> StudentRepository/ParentGuardianRepository/StudentClassAssignmentRepository -> students/parents/student_parent_mapping/student_class_assignments. `admitStudent` calls StudentFeeAutoAssignmentService and the actual hostel/transport services inside the admission transaction. `updateClassAssignment` always sets active=true but its predecessor deactivation is guarded by the *old* assignment's active flag. `resolveParent` only looks up email; missing email always saves a fresh parent.
- Staff: `teacher_management_page.dart` -> TeachersRepositoryImpl/TeachersRemoteDataSource -> TeacherController -> TeacherService -> TeacherRepository/TeacherAcademicAssignmentRepository/TeacherDocumentRepository -> teachers/teacher_academic_assignments/teacher_documents. `createAssignment` synchronizes active academic mappings, `deleteAssignment` only soft-deletes TeacherAcademicAssignment. `profile` returns literal attendance/payroll placeholder text.
- Exams: `exams_page.dart` -> ExamsRepositoryImpl/ExamsRemoteDataSource -> ExamsController -> ExamService -> exam repositories -> V15/V16 tables. `ExamScheduleSubjectRequest` only has subjectId/examDate/maxMarks/passingMarks. `grade` hard-codes bands. `ResultGroup` keys on academic year, class, section and examTypeId; `orderedScheduleSubjects` and marksBySubject key only by subject UUID, merging separate exams of one type. Generic records exports in the same controller are separate from typed marks/results and are not evidence of working typed exam reports.
- Attendance: `attendance_page.dart` -> AttendanceRepositoryImpl/AttendanceRemoteDataSource -> AttendanceController -> AttendanceService -> AttendanceRecordRepository -> student_attendance. `student_attendance_tab.dart` -> StudentProfileApiService -> StudentController attendance-history endpoint -> same AttendanceService/repository. Teacher equivalent flows through TeacherAttendanceService and teacher_attendance. DashboardService.todayAttendance directly calls findTodayDashboardRecords; this existing integration should be preserved. `AttendanceAbsenceNotificationScheduler.run()` only logs execution.
- Tests inspected: AcademicHierarchyServiceTest (teacher replacement/addition), StudentServiceTest (admission, parent add/list, duplicate admission, primary-parent validation, class switch, paginated search), ExamServiceTest (multi-subject schedule validation/update, marks bounds, passing marks, profile pending/results), AttendanceServiceTest (filtered summary/date-range validation). No dedicated TeacherService, TeacherAttendanceService, generated-document service, parent portal, or frontend workflow tests were present in this inspected baseline. Test results belong in the consolidated root report; source inspection alone is not a passing test.

## Implementation priorities from this subset

1. Data correctness: stable parent identity, inactive-assignment reactivation and same-day history invariants; reconcile academic/teacher assignment lifecycle without deleting historical rows.
2. Complete compatible exam subject date/time/room fields, marks/result identity correctness, and configurable grading.
3. Connect certificate UI to preview/generate/history/download/reprint and ensure the stored PDF matches its number, issue date, school, academic year and template version.
4. Correct attendance/profile/dashboard consistency; implement notifications from actual attendance records, historical rosters and monthly aggregation.
5. Parent ownership/account binding, non-teaching staff/HR, timetable/syllabus/lesson plans/calendar/progression and remaining reports are substantial missing features. Do not represent generic module_records CRUD as implementation of these business workflows.
