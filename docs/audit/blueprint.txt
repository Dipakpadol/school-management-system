Recommended principle: Do not develop every portal as a completely separate system. Build one central Java
backend/database with Role-Based Access Control (RBAC). When the Super Admin changes information, the
appropriate information can automatically appear in the Teacher Portal, Parent App, Student Portal, and Admin Portal
according to permissions.
4. Role-Based Access
 Role
Main Access
Super Admin
Full system access and control; manages school configuration, users, roles, permissions, reports,
security, backups, and all modules.
Admin
Administrative management according to permissions assigned by Super Admin.
Principal
Academic/administrative oversight, student/staff monitoring, examinations, attendance, reports and
approvals.
Teacher
Assigned classes/subjects, timetable, attendance, homework, marks/exams, communication and student
academic information.

5. Important Development Guidance
 Use one central School Management System backend/database.
 Implement Role-Based Access Control (RBAC) from the beginning.
 Keep modules interconnected so student, parent, teacher, fee, attendance and examination information stays
consistent.
 Keep government/board-style academic requirements configurable instead of hard-coding them to one board.
 Make Exam, Student Records, Attendance, Promotion, Report Card, and document/certificate modules configurable.
 Maintain audit logs for important data changes and administrative actions.
 Include database backup, restore and backup history.
 Design APIs so web portals and mobile apps can use the same backend.
 Use secure authentication, permission checks, password policies, failed-login monitoring and session controls.
 Provide PDF/Excel export for important reports.
 Keep the architecture extensible so additional modules can be added later.

8. Core Objective
Star International School Management System should work as a complete, interconnected solution for academic,
administrative and operational management. The Super Admin should have centralized control, while every other user
sees only the modules and data permitted by their role.
This document is intended to be used as the initial functional blueprint before database design, API development, UI development,
mobile-app development, testing and deployment.
